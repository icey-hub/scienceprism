# 项目工作区

进入项目后，左侧按「功能 / 系统」分组。首页沿用原来的入口；项目内部采用浅色侧栏、列表和详情布局。侧栏可折叠，当前项目的折叠状态会保存在浏览器中。

## 从功能开始

| 入口 | 用途 |
| --- | --- |
| 仪表盘 | 查看下一步、待审批、近期任务、实际运行和证据状态。统计标明查询范围，未报告的用量不会补成零。 |
| 对话 | 打开当前项目的助手。模型提议的文件修改仍需人工审阅与应用。 |
| 任务与会话 | 找到研究阶段、Harness、实验或编译任务，进入统一详情。 |
| 资料库 | 查看现有项目资料。 |
| 探索 | 切换执行链路与证据链路，查看记录之间的明确关联。 |
| 工具执行 | 打开文件、助手、论文检索、网页检索、识图、绘图、评审和协作；也可进入现有模板迁移。 |
| 运行记录 | 查看已有运行与恢复入口。 |
| 工作空间 | 打开文稿编辑器、编译、PDF、日志及原工具面板。 |

八阶段仍按方向、检索、筛选、复现、创新、方法、实验、写作推进。阶段入口放在仪表盘的下一步及工作空间上下文中，不占单独的一级导航。旧 `/editor/:projectId/research/:stage` 链接仍可打开；创新的路径为 `innovation`，领域记录 ID 为 `ideation`。

在同一编辑会话中切换工具会保留当前文件和未保存草稿。转到另一项目会建立新的编辑会话，关闭旧工具的结果发布。网页检索的「停止后续步骤」等待当前请求结束后停止后续请求，不表示供应商请求已经取消。网页笔记和引用写入仍由用户明确操作，正文插入位于文档正文范围内。

## 任务详情

详情分为摘要、会话、执行、证据、产物和日志。工具执行显示已记录的参数、结果、错误及调用身份；日志保留实际 Runtime 事件。旧记录缺少字段或只有归档摘要时显示缺口。

开始、暂停、恢复、取消、重试、接受、拒绝和应用 Patch 使用原服务。恢复任务不意味着恢复了原 SDK 会话；重放和新 attempt 会显示其实际来源。先接受运行结果，再选择要应用的 Patch；应用时仍检查文件版本和项目能力。

实验计划、阶段批准、Run 批准与科学核验是分别记录的动作。运行完成不自动批准阶段、不自动应用修改，也不自动证明科研主张。

## 探索记录

- **执行链路**：阶段、Harness Run、父子委派、重放、工具调用、实验与产物。
- **证据链路**：Ledger 材料、独立版本、主张、支持关系和显式反例。

点击节点或连线查看原始来源字段，打开源记录或下载记录路径当前的文件。旧引用下载会说明它不是引用保存时的文件快照；请核对版本。图页本身仅查询保存的记录，刷新不会批准或启动任务。

执行图以方向、检索、筛选、复现（可选）、创新、方法、实验、写作八阶段为横向主干，待开始阶段也可见。阶段之间的灰色虚线表示流程顺序，阶段下的实线表示已保存的 Run / 工具调用 / 产物关联；顺序不表示已经执行或获批，跳过复现也保留阶段记录。底部八阶段定位条或「定位当前阶段」可以跳到对应位置；选中阶段后「打开源记录」回到原人工输入与审批页。

实际分支从左到右展开：父级任务 → 子任务 / 调用 → 产物或引用；旧 Run 也按其保存的阶段字段归入阶段。没有明确阶段关联的记录单独展示，不从标题猜归属。节点卡片显示类型、状态和版本；左上角悬浮图例说明类型及连线，选中节点或连线后才展开右侧详情，点击空白或按 Escape 收起。

首次打开使用可读缩放，可拖动画布继续查看，点击「适配画布」查看全图。「横向重新布局」恢复自动布局；旧版本保留的位置可以用「恢复旧布局」取回。使用类型 / 状态筛选、缩放和列表视图逐项阅读；节点详情的「只看相关记录」查询该节点及其直接邻居，「显示全部记录」返回完整查询范围。工具调用可以在任务节点详情中折叠。视口、节点位置和折叠状态按项目、视角和邻接范围保存在浏览器中；选中项保存在 URL，刷新后仍可定位。

`unsupported` 表示缺少支持，`stale-reference` 表示旧版本引用，`contradicts` 表示明确保存的反例，`human-confirmed` 表示来源已由人工确认。它们不等于科学结论有效。图页显示节点 / 调用查询上限以及缺失或截断提示。

## 系统入口

| 入口 | 当前行为 |
| --- | --- |
| MCP | 项目级服务器配置、绑定、手动发现、工具 schema 和显式检查。 |
| 模型 | 原浏览器模型设置，包括端点、模型、运行时及检索 / 视觉覆盖；作用于该浏览器中的项目。后端环境变量仍作为后备值。 |
| Agents | 已有八个固定角色的职责、能力上限、阶段与 Skill 绑定、相关运行。 |
| Skills | 有效目录、实际来源、正文预览和阶段绑定。项目覆盖会标明当前实际生效来源。 |
| 审批记录 / 项目设置 | 原人工决定、项目能力和约束配置。 |

Skill 被选择或绑定、正文被工具读取、模型实际遵循指令是不同事项。工具目录分别展示绑定 / 选择记录与可确认的正文读取，不从选择数量推算使用频率。调用统计只覆盖最近最多 100 条 Run 中保留的调用身份；归档、截断和没有调用 ID 的历史另行提示。

## MCP 的当前范围

MCP 配置保存在项目 `.scienceprism/mcp.json`；支持 `stdio` 和 `streamable-http`。在 MCP 页面添加或保存配置，明确角色、任务、工具名与 `project.read` 能力，然后手动发现工具。发现可能启动配置的进程或连接服务器；仅查看已存目录不会启动连接。禁用服务器后不能发现或发起新检查。

环境变量和请求头的值不返回浏览器；页面只显示键名。编辑时省略 `env` / `headers` 保留原值，提供对象则替换对应组。凭据填写在这些字段中，避免放入命令、参数或工具描述。保存冲突会要求重新读取，失败时保留输入。

**显式检查**使用独立 MCP adapter，要求成功发现、工具声明 `readOnlyHint`、schema 一致以及明确的角色 / 任务 / 工具绑定。HTTP 检查还须符合项目网络允许列表。实际结果进入原 Harness Run，任务详情显示 `mcp__服务器__工具` 的调用和结果。未知、禁用或未绑定工具在调用前拒绝；检查完成不会产生 Patch，也不计为科研核验。服务器的只读声明是协议声明，配置的进程仍由该服务器实现。

**DeepSeek Harness 的自动 MCP 工具调用仍受限。** 当前 SDK 接线尚未证明能够在工具执行前强制应用项目策略，因此拒绝这条自动调用路径；手动发现与显式 MCP 检查可用。SDK 被检测到不等于模型或 MCP 自动执行已就绪，Legacy 降级也不会假装执行了 MCP 工具。

项目备份剔除 MCP 的环境变量、请求头值和 URL 查询参数。恢复后的服务器禁用、发现结果清空；重新填写连接配置和凭据、启用并发现后再检查。原运行和来源 ID 保留。
