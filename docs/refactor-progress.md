## 🔍 EditorPage 结构分析

### 主要职责（需要拆分）

1. **文件树管理** (~800 行)
   - 文件列表渲染
   - 拖拽排序
   - 重命名、删除、新建
   - 上传文件
   
2. **CodeMirror 编辑器** (~1000 行)
   - 编辑器配置
   - 扩展和插件
   - 编译错误标记
   - 自动补全
   - 协作（Y.js）

3. **AI 助手** (~800 行)
   - 对话界面

   - Skill 选择
   - Run 管理

4. **编译系统** (~600 行)

   - 日志查看

5. **其他功能** (~1000 行)

6. **布局和状态** (~700 行)
   - 侧边栏控制
   - 视图切换
   - 全局状态
   - 事件处理

## 📝 提取原则

1. **单一职责** - 每个模块只做一件事
2. **清晰接口** - 通过 props 传递数据，不直接访问全局状态
3. **独立测试** - 每个模块可以独立测试
4. **渐进迁移** - 先提取，再优化，保证功能不变
5. **保留兼容** - EditorPage 暂时保留旧代码，新模块稳定后再删除

## ⚠️ 风险和应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|---------|
| 模块间依赖复杂 | 高 | 中 | 先提取纯展示组件，再处理状态 |
| 状态管理混乱 | 高 | 高 | 使用 Context 或状态提升 |
| 测试失败 | 中 | 高 | 每次提取后立即运行测试 |
| 协作功能冲突 | 中 | 中 | Y.js 保持独立，后续优化 |
| 性能退化 | 低 | 中 | 保持代码结构，不做提前优化 |
