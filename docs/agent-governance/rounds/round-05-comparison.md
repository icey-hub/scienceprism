## 4. 本轮最有价值的产出

### ① 约束治理闭环完成（047）

到本轮结束，约束的**每一面都是代码投影**：

| 面 | 来源 | 门禁 |
| --- | --- | --- |
| 人面向清单 | `renderConstraintTable()` | **整表比对** |
| 机器审计 | `renderConstraintCatalog()` | 投影一致 |
| 强制点 | `enforcement.module:symbol` | 动态 import 校验真实存在 |
| 测试引用 | `testRef` | 校验测试文件里真有同名 `test()` |
| 溯源 | `provenance` | 枚举校验 |
| 漂移 | `drift` | **0** |

**"文档撒谎"在结构上不可能再发生了**——文档是渲染出来的，手改会被门禁拦下并提示"去改注册表"。

### ② 失败从"直接死"变成"自我修复"（044）

模型输出不合契约时，把**校验错误逐条回喂**重试一次。三条边界：**只重试校验失败**（传输失败属 Run limit）、**严格串行**（U-20 共享网关）、**有界**（最多 2 次）。

**这个功能的前提是前面几轮的成果**：如果契约还像最初那样只给字段名，回灌也只会喂回一堆没用的报错。

### ③ 三次"语义重复"收敛（042 / 045 / 048）

| 收敛 | 重复数 | 漂移后果 |
| --- | --- | --- |
| 阶段词汇 | 2 → 1 | 两套词汇互不兼容，tsc 报错看不出原因 |
| 敏感目录表 | 2 → 1 | **隔离缝隙**：一处拦住、另一处放行 |
| "Run 已结束" | 4 → 1 | 已结束的 Run 永远显示进行中 / 决定被错误拒绝 |

## 5. 一次"不该合并"的判断（048）

扫描发现 `taskCenter.js` 有**同一字面量**，但：

- 它属于 **task 词汇**（`TASK_STATUSES` 还含 `queued`/`rejected`）
- **"任务结束"与"Run 结束"不是同一概念，只是字符串巧合**

→ **保留并加注释说明为何不合并**，门禁还断言它不得被"顺手合并"。

**这条与三次合并同等重要**：机械地"看着像就合并"会在语义分岔时埋雷。

## 7. 决策与遗留

### 本轮决策
- **角色在运行前可见**，且面板列出**该阶段全部适用角色**而非硬编码某一个。
- **失败重试只针对校验失败**，传输失败交给 Run limit；重试串行且有界。
- **词汇与常量收敛到单一来源**，但**taskCenter 那处有意不合并**（语义不同）。
- **约束表改为生成物**，文档里明确写"请改注册表"。

### 遗留（进入 Round 6）
1. **前端面板未经浏览器目视确认**（应用未启动）——类型检查与构建通过，接口端到端实测通过。
2. **剩余 3 组重复字面量**（低价值）：`0|false|no`、`cancelled|completed|failed|rejected`（experimentRunner × taskCenter）、`abstract|authors|title|url|year`（paperCandidates × qualityGate）。
3. **绘图未验证项**：TikZ 版细胞图未渲染（需联网预热缓存）、matplotlib 版未渲染、SVG→PDF 未做。
4. **五个既定目标早已全部达成**；Round 6 的选题**需与用户确认**（继续深化 / 转向新需求 / 停止）。
