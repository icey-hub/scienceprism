## 4. 本轮最有价值的发现：**漂移描述本身也会不准**

四次收口里，**三次**的登记描述与代码实情不符，而且**两次方向相反**：

| 约束 | 注册表原记 | 读代码后的实情 |
| --- | --- | --- |
| C-09 | "Harness 路径不查网络白名单" | 该说法误导（legacy 不发工具事件、deepseek 启动前 fail-closed）；**真正的问题是空白名单 fail-open**——**代码比文档松** |
| C-11 | "不确定性字段全为可选、无代码要求" | **反了**：代码对任何非 supported 的 claim 一律报错，**把契约允许的行为也拒了**——**代码比文档严** |
| C-10 | "legacy 不接收 limits" | 属实，但根因是 `adapter.run` 调用处漏传，而非适配器不处理 |
| C-04 | "actor 由调用方自报" | 属实，但**真正的缺陷是末尾那个 `\|\| 'human'` 缺省**——最容易被忽略的一行 |

**结论**：漂移记录是"人写的怀疑"，不是事实。**每拍都必须先读代码**。这已成为稳定工作方式，并写进 `playbooks/verification-discipline.md`。

## 5. 第二条主线：R-15 与 C-17

R-15（"科研工具产出写入 `aidoc/`"）**与 C-07 同一类问题——碰巧成立**：

- 产品里**根本没有 `aidoc` 概念**；`aidoc/` 有东西，只因为驱动脚本从 **gitignored 的 `.env`** 继承了 `SCIENCEPRISM_DATA_DIR`。
- **新克隆跑一遍不会落到 `aidoc/`。**

处置后：落点策略进了产品模块（`documentLanding.js`），驱动脚本**钉住**落点并在越界时**失败**，并注册为 **C-17**。

**C-17 的意义**：它是注册表里**第一条来自用户需求**（R-15/U-21）的约束——不是 ADR 推出来的，也不是 AI 臆造的。这正是你要的"约束以代码形式加，且可选择加不加"的第一次真实落地。

## 7. 决策与遗留

### 本轮决策
- **网络空白名单 = 拒绝一切主机**（与 `capabilityPrompt` 长期告诉模型的话一致），而不是"空白名单 = 任意主机"。
- **不确定性只保留一条强制通道**（`unsupportedClaims` 点名 claim id），其余字段降为可选提示。
- **审批决策必须有身份**，且身份取值受校验——宁可拒绝也不默认成"人类"。
- **新增 C-17 并把 R-15 落进代码**；`aidoc/` 落点由产品策略钉住，不再依赖 gitignored 的环境文件。
- **不为"看着像死代码"而删**：`registerHarnessAdapter` / `registerResearchSourceAdapter` 有文档承诺作依据，保留并注释；本轮它还在 034 的测试里**真正派上了用场**。

### 遗留（进入 Round 5）
1. **前端未展示角色 / 能力 / 可用 skill 摘要**（运行前可见性）。
2. **失败重试回灌未做**：模型输出不合契约时直接失败，未把校验错误回喂重试。
3. **`docs/project-constraints.md` 尚未整表由注册表生成**（目前靠门禁比对 id 集合）。
4. **剩余 5 组重复字面量**（敏感目录表、论文元数据字段、run 状态跨 3 模块、真值集合、`cancelled|completed|failed`）——低价值，待定。
5. **绘图未验证项**：TikZ 版细胞图未渲染（需联网预热缓存）、matplotlib 版未渲染、SVG→PDF 未做。
6. **五个既定目标已全部达成**；Round 5 的选题需与用户确认（是继续深化，还是转向新需求）。
