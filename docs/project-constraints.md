# Project Constraints

This document turns the research invariants into an executable constraint catalogue. The **Module** column names the owner; the **validation location** is the current Seam or the planned Seam when the capability is not implemented yet.

| ID | Constraint | Module | Validation location | Failure behaviour | State |
| --- | --- | --- | --- | --- | --- |
| C-01 | Every workflow operation is scoped to an existing Project and its project-local storage. | Project Root Module | `apps/backend/src/services/projectService.js:getProjectRoot`; `apps/backend/src/utils/pathUtils.js:safeJoin`; workflow file resolution | Unknown Project returns `404 PROJECT_NOT_FOUND`; invalid path is rejected by the path Module. | Current |
| C-02 | Only the current Research Stage can be changed or approved. | Research Workflow Module | `apps/backend/src/services/researchWorkflow/stateMachine.js:currentStage` | Returns `409 STAGE_GATE` with current and requested stage IDs. | Current |
| C-03 | A stage cannot be approved without data satisfying its readiness requirement. | Research Workflow Module | `apps/backend/src/services/researchWorkflow/stageContracts.js:getStageReadiness` and `stateMachine.js:applyApprovalDecision` | Returns `409 STAGE_NOT_READY` and names missing requirements. | C-04 | AI output cannot approve a stage, select a paper, choose an innovation, authorize an experiment, or submit a final claim. | Research Workflow Module + Research Harness Adapter | `approveResearchWorkflow`; `select-papers` quality gate; `run-experiment` plan-only route; `apps/backend/src/services/researchResearch/harnessAdapter.js` | AI output is returned as data or a proposed Patch. | C-05 | Structured Harness output must validate against the named stage contract before it is treated as usable output. | Research Stage Contract Module | `apps/backend/src/services/researchResearch/schemas.js:parseResearchStageOutput`; `harnessAdapter.js:runResearchHarnessStage` | `validation.ok=false`, `output=null`, and the run is not considered successful. | Current |
| C-06 | A Paper Candidate is selectable only when the server-side quality gate returns `accept`; unknown metadata remains reviewable rather than silently accepted. | Paper Quality Gate Module | `apps/backend/src/services/researchResearch/qualityGate.js:applyQualityGate`; `routes/researchWorkflow.js:select-papers` | Returns `409 QUALITY_GATE` with blocked paper IDs; unverified candidates remain `needs-review`. | Current |
| C-07 | Harness work runs in a temporary project copy; original files change only through an explicit Patch application. | Harness Runtime Module | `apps/backend/src/services/harnessRuntime/index.js:copyWorkspace`, `collectPatches`, and temporary workspace cleanup | A failed run returns `ok=false` and does not mutate the original Project. ## Constraint Ownership Rule

The backend is the authoritative interpreter of Project Constraints. The frontend may display a projection of a constraint or failure, but it must not infer permission, readiness, quality acceptance, or approval from local state.
