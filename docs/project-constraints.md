## Constraint Ownership Rule

The backend is the authoritative interpreter of Project Constraints. The frontend may display a projection of a constraint or failure, but it must not infer permission, readiness, quality acceptance, or approval from local state.

## Harness Adapter Enforcement

The DeepSeek Adapter passes the complete capability policy into the model
prompt, but the prompt is not treated as a security boundary. Its child process
receives an explicit environment allowlist (`PATH`, locale/timezone values,
provider configuration, and isolated `HOME`, XDG, and temporary directories),
so unrelated parent-process secrets are not inherited.

The current DeepSeek SDK does not expose a pre-tool hook that can authorize a
network request or command before it runs. Therefore `research.search` and
`experiment.execute` fail before SDK startup with
`CAPABILITY_POLICY_UNENFORCEABLE`, even when the Project grants them. Use the
Legacy Adapter for those capabilities. Unknown tool events also fail closed
with `TOOL_CAPABILITY_UNKNOWN`.
