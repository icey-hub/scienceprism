# 论文工作台改造任务清单

> 2026-10-02，用户已授权实施。范围与取舍见 [计划](plan.md)。状态按实际验证更新。
> 旧的已完成清单见 [归档](../docs/agent-governance/archive/writing-delegation/todo.md)。

每个任务按“完成一条路径 → 聚焦验证 → 删掉被替代路径 → 更新实际状态”推进。涉及 UI 的任务用真实浏览器验收；实现切片收尾运行 `npm run quality`。下面给出额外的具体验证，不能只以测试数认定完成。列出的新增文件名是建议，实施时允许依照最终边界调整。

## T00：固定三个任务基线和入口处置表

**说明：** 用固定 LaTeX 样本记录润色、编译排错、引用核对的当前路径，确认本计划中的静态问题产生什么实际影响。
- [ ] 三类任务有输入、预期结果、操作步骤、版本 / 配置和失败记录。
- [ ] 每个主要入口标明保留、合并、收起或验证后删除，并列出旧链接 / 数据的去向。
- [ ] 候选界面流程可以逐步讲通，不以新增角色或阶段填补缺口。
**验证：** 当前浏览器操作记录；固定样本的编译与引用元数据核对。真实模型基线按实际配置串行运行，未测项明确标注。
**依赖：** 用户审阅计划。
**可能涉及：** `tasks/plan.md`、本清单、`docs/agent-governance/workbench-validation.md`、仓库内 `.cache/workbench-baseline/`。小。

## T01：普通助手请求复用现有 Run 生命周期

**说明：** 先收口普通问答 / 编辑的后端执行，保留旧请求兼容入口，让前端尽早取得 Run ID 并查询实际状态。
- [ ] 问答 / 修改使用同一运行生命周期，能力仍有区别；自动补全和专用服务边界明确。
- [ ] 创建、查询、取消与重复提交有确定结果；普通请求失败不伪装成功。
- [ ] 既有约束提案、已批准回复约束、角色限制和模型配置继续生效。
**验证：** `node --test apps/backend/test/agentService.test.js`，补相应路由集成回归覆盖问答、修改、约束和取消。
**依赖：** T00。
**可能涉及：** `routes/agent.js`、`services/agentRuntime.js`、`routes/harnessRuns.js`、`api/client.ts`、后端 Agent 路由测试。中。

## T02：编辑器使用一个助手入口与真实状态

**说明：** 合并普通 Chat / Agent 的提交与显示，用现有 Run 数据恢复本项目历史和待审阅结果。
- [ ] 默认操作不要求用户选择 direct / tools；用户可理解并选择只读问答或提出修改。
- [ ] 界面显示真实运行状态、工具与终态，停止可用；删除全文返回后的逐字播放。
- [ ] 刷新 / 切回项目后能找回运行和结果；同一任务重复点击不重复提交。
**验证：** 浏览器走通发送、停止、失败、重复点击、刷新；核对界面 Run ID 与后端事件一致；`npm run typecheck`。
**依赖：** T01。
**可能涉及：** `EditorPage.tsx`、新 `editor/useAssistantRun.ts`、新 `editor/AssistantPanel.tsx`、`api/client.ts`、对应样式。中。

## T03：任务输入与文稿版本一致

**说明：** 消除编辑器内容、磁盘内容和 AI 上下文之间的隐式偏差；任务与后续提案关联实际读取的版本。
- [ ] 启动前保存本次参与的草稿 / flush 协作内容；保存失败时任务不启动。
- [ ] 选区、用户补充、必要历史和相关材料进入预算内上下文；界面能查看实际包含的范围。
- [ ] 工具读取和提案记录基准版本；前端不再附加后端已经打包的整份项目文本。
**验证：** 未保存选区、保存失败、文件运行中变化、长上下文和追问回归；使用真实 SDK 配合模拟 HTTP 检查实际模型输入。
**依赖：** T02。
**可能涉及：** `editor/useAssistantRun.ts`、`harnessRuntime/contextPackager.js`、`services/agentService.js`、`harnessRuntime/index.js`、相关集成测试。中。

## T04：服务端统一修改预检与失败恢复

**说明：** 完善现有 Run apply，在写入前校验所选提案的基准版本、路径和现行规则，并明确多文件写入失败的恢复。
- [ ] 文件已变化、路径受限或内容不合规时拒绝应用，返回具体冲突，用户的新内容保留。
- [ ] 多文件先预检；写入中故障能恢复或留下可恢复记录，磁盘状态与应用记录一致。
- [ ] 重复应用不重复写入，按文件选择的范围准确；Run 与人工决定可追溯。
**验证：** 在第二个文件写入处注入失败；负向验证旧版本、创建 / 删除、重复应用和策略变更。
**依赖：** T03。
**可能涉及：** `harnessRuntime/index.js`、`harnessRuntime/repository.js`、新修改应用模块、`routes/harnessRuns.js`、后端 Patch 测试。中。

**依赖：** T04。
