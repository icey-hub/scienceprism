# 真实子 Agent 试点任务清单

任务按顺序执行。每项以独立、可验证的提交结束；完成两项后运行全量质量门禁。

## 任务 1：父子 Run 谱系与权限

**说明：** 在 Harness Run 持久化结构中加入父 Run ID、子任务类型、委派深度；创建子 Run 时由服务端验证同项目、深度上限与能力收窄。明确关联 Run 的保留策略。

**验收标准：**
- [x] 子 Run 能通过父 Run ID 查询，父子关系在重新读取存储后保持一致；不存在跨项目、循环或超过 1 层的委派。
- [x] 子 Run 申请超过父 Run、角色或项目策略的能力时被拒；试点子 Run 的实际能力仅有 `project.read`。
- [x] 超过 100 条历史 Run 后，仍能查到阶段任务引用的父子运行或得到明确的归档记录。

**验证：** 聚焦 Harness Runtime 测试覆盖权限负例、持久化和历史截断；`npm run quality`。

**依赖：** 无。

**预计涉及：** `apps/backend/src/services/harnessRuntime/index.js`、其持久化模块和相关测试。中等。

## 任务 2：串行委派编排器

**说明：** 新建写作审查编排服务：创建协调 Run，按顺序启动两个 `paper-reviewer` 子 Run，将限定长度的审查结果和 Run 引用交给协调 Run。定义超时、取消、失败与重试语义。

**验收标准：**
- [x] 模型调用顺序为子任务 1、子任务 2、协调生成；最大同时请求数为 1；子任务最多 2 个。
- [x] 任何子任务失败或取消时，编排停止并标明失败 Run；重试不会重复已成功的子任务，也不会跳过失败信息。
- [x] 协调 Run 的输入含两个子结果及其来源标识，不能把审查意见标为已确认的证据。

**验证：** 假 Harness 注入测试覆盖顺序、失败、取消和恢复；完成任务 1–2 后运行 `npm run quality`。

**依赖：** 任务 1。

**预计涉及：** 新编排服务、Harness 生命周期接口和测试。中等。

## 任务 3：写作阶段接入与契约校验

**说明：** 在 `handoff-writing` 接入可选择的多 Agent 模式，保留现有单 Agent 路径。阶段任务记录整个编排及各 Run 状态，协调输出沿用现有 Schema、Evidence Ledger 校验和人工确认。

**验收标准：**
- [x] 默认单 Agent 行为与此前一致；显式选择多 Agent 时生成 1 个协调 Run 和 2 个子 Run。
- [x] 子 Agent 的意见不能直接写入 Evidence Ledger 或使阶段自动通过；校验失败保持 `failed`，成功保持 `awaiting_approval`。
- [x] 阶段任务和写作 Brief 能追溯各子 Run；已有阶段任务数据仍可读取。

**验证：** 写作工作流集成测试覆盖两种模式、证据负例和旧数据兼容；`npm run quality`。

**依赖：** 任务 2。

**预计涉及：** `researchWorkflow/application.js`、`stageTask.js`、写作阶段测试。中等。

## 任务 4：在研究界面展示委派过程

**说明：** 在写作阶段提供模式选择与父子 Run 列表，显示每个任务的职责、状态、错误、结果摘要和可用量；保留现有人工确认入口。

**验收标准：**
- [x] 用户能选择多 Agent 模式，并看到两个子 Run 与协调 Run 的真实 ID 和状态。
- [x] 子 Run 失败时界面指向失败任务；成功时可阅读审查意见并查看最终 Brief。
- [x] 单 Agent 模式及历史无子 Run 的阶段任务正常显示。

**验证：** 前端类型检查与构建；在 SciencePrism 本地界面手动运行假适配器流程并检查显示；完成任务 3–4 后运行 `npm run quality`。

**依赖：** 任务 3。

**预计涉及：** `ResearchWorkspacePage.tsx`、API 类型、写作阶段组件及样式。中等。

## 任务 5：真实流程验收与文档

**说明：** 用当前项目的写作工作流试运行一次多 Agent 模式，记录各 Run、校验结果、人工确认状态、耗时与模型用量；据此决定是否扩展其他阶段。

**验收标准：**
- [ ] 三个 Run 的父子关系、各自输出和最终 Brief 能在产品中查看；人工未确认前阶段不前进。
- [ ] 记录相对单 Agent 模式的耗时、用量、审查所得的具体问题及失败情况；不把未验证的模型意见写成研究事实。
- [ ] 用户文档说明启用方式和限制；`npm run quality` 全绿，工作区无额外产物或密钥入库。

**验证：** 本地 SciencePrism 流程检查、`npm run quality`、`git diff --check` 和提交前文件审查。

**依赖：** 任务 4。

**预计涉及：** 项目真实工作流产物、README/研究流程文档与验收记录。中等。

## 检查点

- [x] 任务 1–2：权限负例、串行顺序、失败与恢复测试通过；全量质量门禁通过。
- [x] 任务 3–4：两种写作模式端到端可用；人工确认与 Evidence 校验不退化；全量质量门禁通过。
- [ ] 任务 5：真实产品流程和用量有记录，计划的全部验收标准满足后再考虑扩展阶段。
