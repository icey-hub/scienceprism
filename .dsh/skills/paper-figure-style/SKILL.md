# Paper Figure Style（CCF-A / SCI 一区）

> **这是安装副本，不是编辑源。** 源件在仓库 `pic/skills/paper-figure-style/SKILL.md`。

给计算机方向论文画图。**先定规格，再画图；画完必须跑校验。**

## 何时用

- 为 CCF-A 会议（CVPR/ICCV/NeurIPS/ICML/ACL/CHI/UIST/SIGMOD/VLDB/CCS/ICSE/OOPSLA…）或 SCI 一区期刊（TPAMI/TKDE/TSE/TNSM/Nature 子刊…）准备插图。
- 数据图、架构图、流程图、定性对比矩阵、小倍数网格。
- 返修时被审稿人指出「图不可读 / 不可访问 / 分辨率不够」。
- **第一次给某个 venue 画图、不确定版式时** → 先复刻一张同 venue 的图做校准（流程见 [`references/05-replication-workflow.md`](references/05-replication-workflow.md)）。

## 何时不用

- 交互式看板、网页可视化（Plotly/Altair/Bokeh）——本 skill 只面向**印刷/投稿**。
- 纯探索性 EDA 草图（还没有投稿目标时）。
- 以 Illustrator/Figma 为主的海报与信息图排版。

## 绘图技巧（从复刻 4 张真实 CCF-A 插图中学到的）

下面每一条都是复刻 CCS / SIGMOD / ICML / VLDB 四张真实论文插图时**实际用上**的手法。**动笔前先查这张表。**

### 一、块的语言：形状本身要携带语义

| 形状 | 表达什么 | 画法要点 |
| --- | --- | --- |
| 圆角矩形（rx ≈ 宽 × 0.2） | 处理 / 判别模块（Classifier） | 浅色填充 + 1.4 描边 |
| **梯形（上边 = 下边 × 0.6）** | 编码 / 压缩模块（Encoder） | **居中收分**；收到 0.3 会显得业余，0.2 才对 |
| **卡片堆叠**（3 个同尺寸方块错位 10–15%） | 多个实例 / 数据集 / 样本 | 前卡画内容，后卡只留边；错位方向决定阅读顺序 |
| **虚线轮廓** | 冻结 / 副本 / 未训练 | **同形状 + `stroke-dasharray`**，不要换成别的颜色 |
| 圆柱 | 存储 / 注册表 | 顶部椭圆 + 矩形 |
| **肘线**（两段直线 + 竖直总线） | 模块间连接 | 比斜线更有「工程感」；总线让多路汇聚可读 |
| 双向箭头 | 对称交互 | 单向箭头 = 数据流方向 —— **用方向本身承载语义** |
| 实心星形 / 特殊标记 | 参考点 / 基线方法 | 用醒目实心标记，不要用文字代替 |

### 二、图标要分件画，不要一笔画

以 Android 机器人为例（CCS 图里出现两次：绿 = 正常，红 = 恶意）：

- **圆顶头** = 上半圆 `A` 弧 + 平底 `Z` 闭合
- **双眼** = 2 个白色小圆
- **双天线** = 2 条从头顶**向上外张**的线（`stroke-linecap="round"`）
- **身体** = 圆角矩形；**双臂** = 两侧小圆角矩形；**双腿** = 底部 2 个小圆角矩形

> 第一版我把头画太大、身体画太扁，结果像一张桌子。**按部件拆开、各自定比例**才对。

### 三、排版：让文字有「家」（**重叠是最常见的翻车点**）

> **先记住这条**：元素重叠 / 遮挡是自绘插图里**最高频**的缺陷，而且**肉眼极易漏** —— 一眼扫过去觉得「还行」，实际已经叠在一起。
> 本 skill 的门禁现在会查它（见第 6 步），**别等渲染后才靠眼睛发现**。

**六条硬规矩：**

- **子图标题放进内容之间的空带**。CCS 图里 (c) 的标题原本压着连接线 —— 先找出上下两组内容之间**没有任何元素**的水平空带，再把标题放进去。
- **白色底衬只铺到线之前**。文字必须压线时，在文字下铺白色矩形；矩形**只铺到线之前**，否则会把箭头/连线一起盖掉（踩过：底衬盖住了肘线箭头）。
- **注释不要横跨网格线**。竖直网格线要么起点下移，要么把注释挪到网格线够不到的位置。（踩过：ICML 图的「n=20 per seed × 3 seeds」被 α=1.0 的网格线穿过 —— 修法是把网格线起点从面板顶下移到 y=6 那一档。）
- **刻度标签与网格线留 ≥2pt 间隙**。刻度在面板**外**、网格线在面板**内**，两者包围盒不该相交。
- **一行文字用一个 `<text>`**。拆成多个 `<text>` 再手工推进 x 会**吞掉空格、字距错乱**（`SELECTFROM`、`WHERE2.0`）。确需多色时用 `<tspan>`。
- **表格用行着色表达类别**，不要靠边框粗细；**面板标题与编号二选一**，不要都上。

**五类重叠/遮挡，门禁都能报出来：**

| 类型 | 判定 | 典型成因 |
| --- | --- | --- |
| 文字 × 文字 | 重叠 > 较小文字面积的 30% | 标签写太长、锚点算错 |
| 文字 × 直线 | 直线穿过文字盒内缩后的核心区 | 注释横跨网格线 / 连接线 |
| **线条 × 图形** | 线从**外部扎进**实心图形超过阈值 | 连接线起点落在图标/方块内部；箭头戳穿模块 |
| **图形 × 图形（重合）** | 两个**小图形**重合 > 30% | 两个箭头画在同一位置；标记点堆在一起 |
| **图形 × 图形（遮挡）** | 后画的实心块把先画的**整个盖住** | 背景块尺寸算错，把内容盖没了 |
| 文字越界 | 包围盒超出画布 | 长标签 + `text-anchor="start"` |

**线条 × 图形**这条最容易误报，判定时必须同时满足三个条件（缺一个就会把正常画法判成缺陷）：

1. 线**画在图形之后**（后画的才在上层）；
2. **两端不全在图形内** —— 两端都在里面是图形自身的内容（如卡片里的节点连线）；
3. 穿透深度 **> 图形较短边的 25%** —— 只是从大容器边缘擦过不算。

**图形 × 图形**同理，判据是「**小**」而不是「重合比例」，因为两种正常画法的重合比例都很高：

| 正常画法 | 重合比例 | 尺寸 | 是否误伤 |
| --- | --- | --- | --- |
| 卡片堆叠（故意错位） | ~60% | 大（≈116 单位） | ❌ 按尺寸卡掉 |
| 容器包住表格（正常嵌套） | 100% | 大（≈220 单位） | ❌ 按尺寸卡掉 |
| **两个箭头画在一起（缺陷）** | 96% | **小（≈16–21 单位）** | ✅ 报出 |

> 实测收益：这条规则抓到了 VLDB 流程图里「红色标注箭头的箭头与黑色树边箭头的箭头画在同一坐标」（96% 重合）——两个箭头叠成一个，肉眼只看到「箭头有点糊」。修法：沿方向缩短 6 单位，或横向偏移到 > 4.4 单位（黑箭头半宽 2.2 × 2）。

**排查手法**：不要靠眼睛扫全图。跑门禁，按报告逐条修，改完再渲染确认。

> ⚠️ **局限**：若 SVG 的文字已被转成路径（论文原始图常见），门禁看不见它们 —— 那时只能靠渲染后目视复核。

### 四、小倍数（facet grid）的硬约定

从 SIGMOD 的 3 行 × 8 列 = 24 面板图学到：

- **y 刻度只标最左列**，其余列一律不标
- **共享轴标签只标一次**：x 标签居中在整图底部，y 标签竖排在整图左侧
- **图例只放一个**，置于整图顶部或底部；不要每个面板都放
- **同质面板用面板标题**（数据集名），**异质面板才用 (a)(b)(c)** 编号
- 网格用**淡灰虚线**，四边封闭边框，刻度朝外

### 五、双编码：不要只靠颜色

从 CCS 散点图学到：**颜色**区分方法（蓝 = Plankton，橙 = GinMaster），**形状**区分状态（圆 = predrift，三角 = postdrift）。

给每个系列分配 `(颜色, 标记形状, 线型)` 三元组，保证任意两个系列**至少两维不同**。
→ **灰度打印后仍能区分才算合格。**

### 六、画布与字号

- **先把画布放大到原图的 2–3 倍再画**，否则字号无法满足 ≥7pt
  （例：原图 653 宽 → 画布 1400；原图 473 宽 → 画布 1419）
- 字号层级：**面板标题 > 轴标签 > 刻度/注释**；同层级全篇统一
- 线宽分层：**网格 0.35–0.6 / 框线与主数据线 0.8–1.2 / 强调 1.5–2.0**
- 画布宽高比按原图定，不要自己发明（原图 3.18 就画 3.18）

### 七、抄「语法」，不抄「内容」

复刻的价值是提取可迁移的**视觉语法**：

- **用线型 + 箭头方向再叠一层语义**，而不只是颜色（实线/虚线/点线）
- **语义色**：一个逻辑分组一个强调色，其余保持黑白灰
- **把「负结果」也画出来**（例：被门禁拒绝的分支用虚线单独标出，而不是省略）
- **SQL / 代码注释用两色区分条件**：蓝 = 命中条件，红 = 违规条件（VLDB 图语法）
- 原图**可能违反规范**（例：ICML 某图用了双 Y 轴）→ 复刻时保留以忠实原图，但生成器里留开关（如 `USE_DUAL_AXIS`）供切换

> 「怎么复刻一张原图来校准风格」的完整六步流程见 [`references/05-replication-workflow.md`](references/05-replication-workflow.md)。

## 流程

> **动笔前先查上面的「绘图技巧」表** —— 形状语义、图标分件、排版让位、小倍数约定、双编码、画布与字号。跳过它就会画出「像 PPT 的框图」。

### 第 0 步：锁定目标 venue 的硬规格（不要跳过）

查 `references/02-venue-specs.md`，抄下四个数：**栏宽 / DPI / 字号区间 / 接受格式**。

速查：

| venue | 单栏 | 双栏 | 图内字号 | 位图 DPI |
| --- | --- | --- | --- | --- |
| IEEE（TPAMI/TKDE/TSE…） | 88.9 mm | 182 mm | ~9–10 pt | 彩色/灰度 >300；黑白线稿 >600 |
| Nature 系 | 88 mm | 180 mm | **5–7 pt** | ≥300 |
| PLOS | 6.68–19.05 cm | — | **8–12 pt** | 300–600 |
| ACM / SIGCHI（CHI/UIST…） | 模板双栏 | 模板双栏 | 与正文协调 | 线稿矢量优先 |

### 第 1 步：先剖析数据，再选图型

**不要一上来就画。** 先回答六个问题（借自 `scipilot-figure-skill` 的「可视化顾问」定位）：

1. 列类型是什么（数值/类别/时间）？
2. 样本量多大？**小样本不要画均值柱**——会掩盖分布。
3. 分布形态？异常值？
4. 有没有分组结构？
5. 变量间相关性？
6. **这张图要支撑哪个论证**？

回答完再按下表选型：

| 数据形态 | 图型 |
| --- | --- |
| 有时间/步数轴 | 折线图（+ 置信带） |
| N 个方法 × M 个基准 | 分组柱状图 |
| 单一排名 | 横向条形图 |
| 两个连续变量相关 | 散点图 |
| 方阵数值 | 热力图 |
| 占比分解 | 堆叠柱（**避免饼图**） |
| 多数据集 × 同一指标 | **小倍数网格**（共享轴标签，一个图例） |
| 系统组件与数据流 | **架构图**（左→右流程 / 分层横带 / 中心辐射） |
| 定性效果对比 | 图片矩阵（行=场景，列=方法） |

**判定规则**：有数值轴 → 数据图；有方框和箭头 → 示意图。

**主动拦截这些经典错误**（发现即改，不要等审稿人指出）：

- 小样本画均值柱掩盖分布
- 双 Y 轴
- 饼图
- Y 轴不当截断
- rainbow / jet 色图
- 把分类点连成折线

### 第 2 步：定画布尺寸

- 单栏图：宽 ≈ 88 mm；双栏图：宽 ≈ 180 mm。
- 高度按内容定；横向 teaser 常见 2:1 ~ 3.2:1；结果图常见方形或纵向。
- **宁可画大**：出版方能把图缩小，但几乎无法放大。
- 零依赖 SVG 路线（本机无 matplotlib 时的唯一选择）：
  - 单栏示意图画布 ≈ 500 × 350 px，双栏 ≈ 900 × 500 px；
  - 手写 SVG 或确定性 JSON→SVG 渲染（**不要**用 AI 生图模型画带标签的图）。

### 第 3 步：定配色（最多 8 个分类色）

```text
分类（按序取用，全篇一致）
C1 #0072B2   C2 #D55E00   C3 #009E73   C4 #CC79A7
C5 #E69F00   C6 #56B4E9   C7 #F0E442   C8 #000000

中性
INK #000000   GRID #AFAFAF   BG #FFFFFF   MUTED #797877

线宽
网格 0.35–0.6   坐标轴/主数据线 0.8–1.2   强调 1.5–2.0
```

- 连续数据：**感知均匀**色图（`viridis`/`plasma`/`inferno`/`magma`/`cividis`、Crameri `batlow`）。
- **禁止** `jet` / `rainbow` / `hsv` 表达需要精确比较的数据。
- 发散数据：中点用中性色（浅灰/白），两端对称冷暖。
- 分类色 >8 个系列时，改用小倍数，**不要**继续加颜色。

### 第 4 步：双编码（强制）

给每个系列分配 `(颜色, 标记形状, 线型)` 三元组，保证任意两个系列**至少两个维度不同**。

| 系列 | 颜色 | 标记 | 线型 |
| --- | --- | --- | --- |
| Ours | `#0072B2` | ● | 实线 |
| Baseline A | `#D55E00` | ▲ | 虚线 |
| Baseline B | `#009E73` | ■ | 点划线 |

**理由**：SIGCHI《Guide to an Accessible Submission》是 CHI 的强制要求——只靠颜色区分元素对色觉障碍读者和黑白打印都不可用。

### 第 5 步：画

- 图内**不写图题/图号/作者名**（图注在正文里）。
- 面板级标题可以有（如 `Before Training` / `After Training`）。
- 同质小倍数：每面板给标题、不编号；异质面板：给 (a)(b)(c)。
- 小倍数：**共享轴标签只标一次**，**图例只放一个**且不遮挡数据。
- 注释直接画在图上：箭头、虚线、色框、inset —— 用**线型**再叠一层语义。
- 条形图从 0 起；不截断误导；不用 3D 图。

### 第 6 步：跑校验门禁（不可跳过）

```bash
node check/check-figure-style.mjs <你的图.svg>
```

校验项：**XML 合法性**、字号 ≥7 pt、线宽在 0.35–2.0、分类色数 ≤8、**未使用 jet/rainbow 色**、
未内嵌位图（架构图）、字体有回退链、图内无图题、
**元素重叠/遮挡/越界（文字×文字、文字×直线、线条×图形、图形×图形、文字越界）**。
**退出码非 0 就是不合格。**

> 两类**最容易被漏掉**的问题，现在都进自动检查了：
> - **重叠/遮挡** —— 字号、线宽、配色全合规的图，仍然可能元素压在一起；
> - **XML 非法** —— 一个未转义的 `&` 就让整张图在浏览器里渲染成错误页，**图等于没画**，而源文件看起来「有内容」。
>
> 门禁会逐条列出「哪段文字被哪条线穿过」「哪条线扎进了哪个图形」，照着改就行。

### 第 6.5 步：渲染后目视复核（自检闭环）

**源文件里有 `<text>` 不等于图能看。** 必须把图渲染成位图**看一眼**：

1. 渲染成 PNG；
2. 检查：**缺字（CJK 方框）、文字被裁切、刻度重叠、图例压住数据、子图未对齐**；
3. 有问题就回改、重渲，直到通过；
4. 再**转灰度看一次**——所有系列是否仍可区分？

> 这一步是本仓库的既有纪律：`figure-table-plan` 明确要求「渲染后**看**光栅化输出；源文件里有文本节点不等于验证通过」。

### 第 6.6 步：中文论文的额外处理

中文期刊/中文论文图需要额外注意（借自 `scipilot-figure-skill`）：

- 字体配置：`Noto Sans CJK` / `Source Han Sans` / `SimHei` 之一，并给足回退链；
- **修复负号方框**：`plt.rcParams['axes.unicode_minus'] = False`；
- 混排惯例：正文宋体 + **数字与英文用 Times New Roman**；
- 中文字宽 ≠ 英文字宽，手写 SVG 时要按**全角宽度**估位，否则标签会溢出容器。

### 第 7 步：导出

| 内容 | 格式 |
| --- | --- |
| 线稿 / 图表 / 示意图 | **矢量**：PDF / EPS / SVG |
| 照片 / 渲染图 / 显微图 | 位图 ≥300 dpi：TIFF / PNG |
| 混合 | 位图置底，矢量元素覆盖其上并保持可编辑 |

- **字体必须嵌入或转曲**（Illustrator `Shift+Cmd+O`；Inkscape `Shift+Ctrl+C`）。
- 单图大小：Nature ≤50 MB，PLOS ≤10 MB。
- PLOS 额外：TIFF 需扁平化、无 alpha、LZW 压缩、留 2 pt 白边。

### 第 8 步：无障碍（ACM/SIGCHI 系强制）

- 每张图给**文字描述**（≠图注，不要复述图注）。
- LaTeX 用 `\Description{...}`；Word 用 Alt Text。
- 表格用真表格，公式用标记公式，**都不要用图片**。

## 反例（一眼判不合格）

1. `cmap='jet'` 或 `rainbow` 画连续数据。
2. 只靠颜色区分 5 条曲线 —— 黑白打印后全变灰线。
3. 图例框压在数据点上。
4. 24 个小面板各写一遍轴标签。
5. 把表格截图当表格、把公式截图当公式。
